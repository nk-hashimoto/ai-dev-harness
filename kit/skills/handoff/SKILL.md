# handoff — 引き継ぎ文書の生成

引き継ぎ先は「**何も覚えていない優秀な同僚**」。会話にしかない情報を回収するのが仕事で、リポジトリを読めば分かることは書かない。

**引数**: 出力先パス(省略時は `docs/handoff/YYYY-MM-DD-<topic>.md`。`docs/` がないプロジェクトではリポジトリの慣習に合わせる)。

## 手順

1. **現実を確認する**: `git status` / `git log --oneline -10` / 現在のブランチ。記憶ではなく git を信じる。未コミット変更があれば、ファイルごとの変更意図を §7 に書けるよう内容を確認する。
2. **テンプレートを埋める**: `~/.claude/norms/templates/handoff.md` の全セクション。優先して回収するのは**会話にしか存在しない情報**:
   - **§4 決定事項と理由**(なぜその設計にしたか / 何を検討して捨てたか)
   - **§5 試して失敗したこと**(再試行させないため。これが抜けると引き継ぎ先が同じ壁に同じ時間をかける)
   - **§7 地雷**(触ってはいけない場所、一見不要だが消してはいけないコード)
   - **§1 スコープ外**(書かないと引き継ぎ先が「ついで」を混ぜる)
3. **次の一手を1つ書く**: 引き継ぎ先が最初に実行する具体的な作業。「続きをやる」ではなく「`X.ts` の `foo()` に Y のケースを追加する」の粒度。
4. **検証コマンドを実際に実行する**: §8 に書いたコマンドをその場で走らせ、記載どおりで green(または既知の red)になることを確認する。同じ差分・環境で直前に検証済みなら結果を参照し、引き継ぎのためだけに再実行しない。終了時刻や環境の制約で実行できなければ未検証と理由を残す。
5. **タスク台帳を同期する**: 実行記録にブランチ・MR/PR・最後に終えた工程・検証の所在・次の操作・この引き継ぎへの参照を残し、担当を中断として記録する。指摘IDと回数は台帳またはMR/PRの記録を引き継ぎ、この文書に複製しない。実装中・レビュー中を完了にしない。
6. **正のドキュメントを現実に同期する**: プロジェクトの CLAUDE.md 等に「現在のステータス」があれば、handoff の §2 と食い違わないよう更新する。
7. 未コミットの変更を残す場合は、その理由を §7 に明記する(コミットできるものはコミットしてから引き継ぐ)。

## 注意

- **リポジトリを読めば分かることは書かない**。ファイル一覧、コードの説明、git log の書き写しは不要。
- **10分で書ける分量に収める**。長い handoff は読まれない。
- 完了済みタスクの handoff は役目が終わっている。内容が今後も要るなら正規ドキュメント(spec / CLAUDE.md / DECISIONS)へ昇華し、handoff ファイル自体は削除する。
- 詳しい原則は `~/.claude/norms/04-handoff-protocol.md`。
