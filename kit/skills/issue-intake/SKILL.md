# issue-intake — 見つけたものを起票するかを判断する

**判定基準は `working-norms.md` の「レビュー指摘の行き先」が正**(起票も申し送りの一形態なので、同じ2関門を通す)。
このスキルが持つのは、その判定に**入る前に引くもの**だけ。

**この確認が要るのは、実装ループの外で見つけたものがどのタスクにも紐づかないから。**
`next-task` はタスクの記述を開くので既存の申し送りが自然に目に入る。
一方、画面を触っていて気づいたもの・人がチャットで挙げたものは、**誰も台帳を開かない**まま起票へ進む。

## 1. 既に記録されていないかを引く

**引く先はプロジェクトの文書から読み取って決める。** 下は台帳テンプレート(`TASKS.md.template`)と
`decision-log` が作る形を前提にした既定で、プロジェクトが別の形を定めているならそちらに従う。

①**未着手タスクに溜まっている申し送り** — 他タスクのレビューで出た指摘のうち、そのタスクでは判定できないものが送られている。**同じものが既に無いか確かめる**  
②**未決の記録**(`decision-log` が作る決定・未決の一覧) — 仕様としてまだ決めていないだけのもので、不具合ではない  
③**意図した割り切り** — 「この層では見つからないことを承知で次の層へ持ち越す」と決めてある類。プロジェクトの実装ルールが定めていることが多い

**申し送りは記号だけで `grep` しない。** 同じ記号が複数の意味で使われる:

| 形 | 意味 |
|---|---|
| `#### ⚠要人間確認`(節見出し) | 人への問い。ループはこの節を持つタスクを飛ばす |
| `- **⚠ …**(出所: …)` | **申し送り**。他タスクから送られた確認項目 |
| `- **⚠ …**`(出所なし) | そのタスク自身の注意書き |

**出所ラベルで絞る**(規範が申し送りに出所の明示を求めているのはこのため):

```bash
grep -n '^- \*\*⚠.*(出所:' <台帳>
```

## 2. 既にあったときの着地

- **①に在るなら、そのタスクが確認する。重ねて起票しない**
  - 例外は**その確認の予定時期まで待てないとき**。見つけた欠陥が、そのタスクより前にやる作業を
    止めている場合がこれに当たる。このときだけ 3 の判定へ進み、
    新タスクの `#### 出所` に**元の行**を書く
- **②に在るなら不具合ではなく未決の材料。** 決められるのは人だけなので、
  プロジェクトの人向けの待ち行列へエスカレーションする。仕様を書き換えるのは決定の**後**
- **③に当たるなら起票しない。** 意図した割り切り

## 3. 無かったときの行き先

**2関門を通す**(判定基準は冒頭が指す正)。**通した結果が「現タスクで直す」なら起票しない。**

起票すると決めたら:

- **`#### 出所` に「どこで見つけたか」を書く。** 後から「そのフェーズで何がどれだけ検出されたか」を
  台帳から読むために要る。実装ループの外で見つけたものは、出所がここにしか残らない

## 注意

- **「あとで決める」を起票の理由にしない。** 規範の第2関門が禁じている形がそのまま当てはまる。
  行き先のタスクがその判断をする材料を構造的に持っているときだけ送れる
- **人が挙げた不具合をそのまま起票しない。** 再現するか、既に記録されていないかを引いてから判断する。
  ただし**引いた結果を伝える** — 「既知でした」で終えると、挙げた側は次から挙げなくなる
