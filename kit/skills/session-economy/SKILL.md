# session-economy — モデル委譲の采配

**起動条件**: ユーザーが明示的に呼んだとき、または大きな作業の着手前に計画を立てるとき。

**前提**: 委譲は無料ではない。サブエージェントは毎回コールドスタートで、こちらが持っている文脈を再取得するところから始まる。**節約になるのは「大きく独立した仕事」を渡したときだけ。**

## 手順

1. **タスクを性質で分解する**:
   - 判断・設計・レビュー(契約を決める、トレードオフを選ぶ、成果物の可否を判定する)
   - 探索・抽出(広範囲の grep、一覧化、事実の収集)
   - 機械的な実装(契約が文章で書けている作業)
2. **委譲するかを判定する。委譲しないものを先に外す**:
   - 数手のツール呼び出しで終わる → **自分でやる**
   - **自分の作業の検証** → 委譲しない。検証は自分の工程
   - 契約(完了条件)を文章で書けない → 委譲できない。**まず自分で契約を固める**
   - 残ったもののうち、大きく独立して並列化できるものだけが委譲対象。**1体で足りるなら1体**
3. **モデルを割り当てる**(どのモデルが上位/下位かは、プロジェクトの CLAUDE.md に置く役割表が正):
   - 判断・設計・最終レビュー → 上位モデル(通常は親セッションのまま)
   - 通常の実装 → 既定の委譲先(下位モデル)
   - 単純な調査・抽出 → 軽量モデル(実装は任せない)
   - **割り当ての表現は定義側に置く。** 世代を固定できるのはエージェント定義の `model:` frontmatter だけで、そこにフルID(`claude-opus-5` / `claude-sonnet-5`)を書く。Agentツールの `model` パラメータはエイリアス(`opus` / `sonnet` 等)しか受け付けず、意図しない世代に解決される。**定義の無い汎用エージェントには世代を固定する手段が無い**ので、世代が問題になる委譲は先に定義を作る。トークン量は同じ定義の `effort:` で絞る
   - 定義の器 — 置き場所は `.claude/agents/<name>.md`(そのプロジェクトだけ)/ `~/.claude/agents/<name>.md`(全プロジェクト):
     ```
     ---
     name: <name>                     呼び出し時の subagent_type になる
     description: <いつ使うか>         呼ぶ側が選ぶための文。対象が増えると陳腐化する固有名詞を書かない
     model: <フルモデルID>             エイリアスを書かない
     effort: low|medium|high|xhigh|max
     ---
     本文 = そのエージェントのシステムプロンプト
     ```
     本文に何を書くか(スコープ固定・書くと逆効果な検証指示)は `~/.claude/norms/05-orchestration-notes.md`
4. **委譲プロンプトに4点セットを必ず入れる**(`~/.claude/norms/02-thought-processes.md` §7):
   1. 完了条件 2. 変更してよい範囲 3. **変更してはいけない範囲** 4. 検証方法
   - 委譲先が上位モデルなら、手順の細分化と検証ステップの明示は書かない(自前でやるので二重になる)。代わりにスコープ固定を強く書く。委譲先が下位モデルなら、逆に手順と検証を明示し、`~/.claude/norms/03-implementation-pitfalls.md` を読ませる。**この出し入れは呼び出し側(このスキルを実行している側)が決める** — 委譲先に自己判定させない
   - 詳しくは `~/.claude/norms/05-orchestration-notes.md`
5. **並列化は読み取り系のみ**。同じファイルを書く複数エージェントを同時に走らせない。
6. **結果を親でレビューする**。重点は「頼んでいない変更が入っていないか」。

## 出力

| 作業 | 実行者(モデル/エージェント) | 理由 | 完了条件 |
|---|---|---|---|

に加えて、委譲しないと決めたものとその理由(判断の記録として残す)。

## 注意

- **委譲の数を成果と取り違えない。** 委譲が増えるほど文脈の再取得コストと統合コストが増える。迷ったら自分でやる。
- サブエージェントは親と別のコンテキストで動くので、ログや中間出力のノイズを親に持ち込まない利点がある。**逆に、親が持つ暗黙の前提は伝わらない** — プロンプトに書いていない制約は守られない。
- エージェント間の報告は事実を削らない(判断材料になる)。短くするのはユーザー向けの文章とディスクに書く成果物の方。
