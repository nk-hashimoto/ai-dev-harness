# ドキュメント構成の棚卸し

**起動条件**: ユーザーが明示的に呼んだときだけ。それ自体が独立した作業なので、他の作業の最中に始めない。

肥大化した常設ドキュメントを、**読まれ方**に沿って割り直す。削るのが目的ではない — **必要な情報が必要なときだけ載る**状態にするのが目的。

## 前提: 効き方の階層

置き場所によって「実際に効くか」が変わる。ここを外すと、作っても効かない仕組みになる。

| 層 | 例 | 性質 |
|---|---|---|
| **機械的** | CI・pre-commit・エディタの保存時処理 | 判断を経由しない。確実 |
| **常時読み込み** | `CLAUDE.md` と `@import`、`README.md` | 全セッション・**全サブエージェント**が無条件で払う |
| **条件付き読み込み** | `docs/` 配下、skill、`norms/01〜05` | 読むと判断されたときだけ効く。**取りこぼす** |

**常時読み込み層のコストは「サイズ × セッション数 × サブエージェント数」**。ここに履歴を置くと最も高くつく。

## 判定の3軸

各ドキュメントの各節に対して、順に問う。

### 1. 単一の正か

同じ事実に権威が2つないか。あるなら**片方をポインタに落とす**(ID + 1行 + リンク)。

- 見つけ方: 識別子(決定番号・タスクID・トークン名)が2つ以上のファイルで**全文**として現れる箇所を grep
- 危険な形: 新しい記述と**上書きされた古い記述が同じファイルに同居**している。grep した実装者が毎回どちらが正かを裁定させられる

### 2. 寿命 — 現在の状態か、履歴か

**履歴は git が持っている。** 版数付きの「vX.Yで〜を変更した」は、タグと `git log` に任せられないか。

- 残す価値があるのは**版ごとの索引**(版 / 日付 / 変わった決定番号)まで。変更内容そのものは決定の記録が持つ
- 「解消済み」「反映済み」と書かれた作業ログは、恒久的な知見を抽出したうえで消す

### 3. 読まれ方 — 誰がいつ読むか

常時読み込み層に、毎回は要らないもの(履歴・過去の経緯・詳細な根拠)が入っていないか。

- 読む単位も見る: **1件だけ欲しいのにファイル全体を読む**構造なら、切り出す手順(`awk`/`grep` のコマンド)を参照側に書く。分割しただけでは丸読みされて効果が出ない

## 削ってはいけないもの(重要)

**「理由が書いてあるか」で判断しない。** 次は規範の一部なので残す:

- **制約の適用範囲を決めている理由** — 消すと実装者が条件を素直に単純化して、防いでいた欠陥が戻る
- **却下した代案** — これが唯一の記録なら、消すと同じ案が再提案される。ただし置き場は規範側でなく決定の記録側でよい
- **受け入れたコストの明示** — 「この制約は満たせないので別の手段で担保する」形の記述

判定は「その一文を消したら、読み手が**別の結論に行き着くか**」。行き着くなら残す。

## 手順

1. **測る** — 常時読み込み層の合計サイズ、ファイルごとの節別サイズ、版数付き履歴行の数
2. **重複を洗う** — 識別子で grep し、2箇所以上で全文が出るものを列挙
3. **上書き関係を洗う** — 「改訂」「上書き」「廃止」を含む記述と、その対象が同居していないか
4. **3軸で仕分ける** — 節ごとに「残す / ポインタ化 / 別ファイルへ移す / 消す」を決め、**理由を1行**添える
5. **削減量と手間を見積もって提案する** — 参照の追従先(タスク台帳・skill・エージェント定義)の件数も数える。**大きい削減が見込めない箇所は触らない**(§10 のような小さい節を削る利得は小さく、載せ替え事故の損失が大きい)
6. **承認を得てから実行する。** 移動は機械的に(`awk` の行範囲抽出など)行い、転記による書き換わりを防ぐ
7. **検証** — 移動後に ①識別子の網羅性(全部がどこかに1回だけある) ②リンク切れ ③参照側が古い記述を指していないか、を確認する

## 落とし穴

- **参照の載せ替え漏れ**。台帳やエージェント定義が旧セクションを指したまま残る。移動のついでに**参照先が現行の記述を指しているか全件突き合わせる**(過去に、上書き済みの決定を指したままの参照が実際に見つかっている)
- **分割しただけでは軽くならない**。参照側が新ファイルを丸読みすれば総量は増える。切り出し手順をセットで書く
- **手を広げすぎる**。依頼された範囲を超えて全ドキュメントを作り直さない。効果の大きい順に、承認を取りながら進める
