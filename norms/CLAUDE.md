# 作業規範(全プロジェクト共通)

**このファイルは常時読み込みの入口。** `~/.claude/CLAUDE.md` に次の1行を書いて読み込ませる。

```
@norms/CLAUDE.md
```

置いただけでは読まれない。**この import を書かないと、下の2ファイルも、それらが課している完了条件も一度も読まれず、しかもエラーは出ない。**

@00-priority-rules.md

@working-norms.md

## 必要時に読むもの(毎回は読み込まない)

パスはこのファイルと同じディレクトリからの相対。

- **設計判断・レビューで迷ったら**: `01-engineering-principles.md`(設計思想・品質基準・レビュー基準)と `02-thought-processes.md`(判断の内側)
- **完了報告の前**: `/self-review` が、作った成果物の種類から読み返す節を決める。手で選ばない
- **実装タスクを委譲するとき**: `03-implementation-pitfalls.md`(失敗14パターン)。**出し入れは委譲元が決める** — 委譲先に読ませるかどうかを、台帳の `#### impl` に書かれた値で判断する。読み手が自分のモデル名から決めるのではない
- **委譲プロンプト・サブエージェント定義・Skill・この規範自体を書く/直すとき**: `05-orchestration-notes.md`(**呼び出し側向け**。実行中に自分のために読むものではない)
- **セッション引き継ぎ**: `04-handoff-protocol.md` + `templates/handoff.md`

## 「上位モデル」「下位モデル」の意味

規範の中でこう呼んでいるのは、**能力の一般的な序列ではなく、この運用での役割**。どのモデルがどれに当たるかは、**プロジェクトの `CLAUDE.md` に置く役割表**が正(`kit/settings/CLAUDE.md.template` §4)。実際のモデルIDは各エージェント定義の `model:` frontmatter にある。

**3役すべてに同じモデルを割り当ててよい。** その場合、規範のうち「上位モデルなら省いてよい」と書かれた項目は**省かない**(省く判断の主体が居なくなるため)。
