## 作業の種類ごとに、着手前に読む節

常時読み込むのは、上の最重要ルールとこの案内だけ。詳細な規範は必要な場面で読む。

**読むのは作業を始める前。** 始めてから読むと、読む前に下した判断が規範と食い違っていても気づけない。
該当する行が複数あれば全部読む。スキル・role 定義が読む節を指定している場面では、そちらの指定に従う。

| 作業 | 読むもの |
|---|---|
| どの作業でも最初に | `working-norms.md`「着手前(必ずやる)」 |
| コード・設定・テストを書く/直す | `working-norms.md`「作業中」「テスト」 |
| 不具合を直す(レビュー指摘や自分の検証で見つけたものを含む) | `01-engineering-principles.md` §7 |
| 型・API・スキーマ・保存済みデータの形式を変える | `working-norms.md`「作業中」と、スキル `impact-scan` |
| 仕様の矛盾・穴・未決に当たった | `working-norms.md`「矛盾・未決の扱い」 |
| レビュー指摘や気づいた課題の行き先を決める(申し送り・起票) | `working-norms.md`「レビュー指摘の行き先」 |
| 作業を委譲する・サブエージェントを起動する・報告の長さを決める | `working-norms.md`「委譲・スコープ・分量」 |
| 委譲プロンプト・role 定義・スキル・規範を書く/直す | `05-orchestration-notes.md`(呼び出し側向け)、スキルなら `skill-design.md` |
| 削除・上書き・force push・外部サービスへの送信 | `working-norms.md`「危険操作」 |
| 文書・コメント・コミットメッセージ・報告を書く | `working-norms.md`「書き方の規約」 |
| 長いセッション・並行作業・ブランチの切り直し・引き継ぎ | `working-norms.md`「セッション運用」、`04-handoff-protocol.md` |
| 設計判断・レビューで迷う | `01-engineering-principles.md`、`02-thought-processes.md` |
| 完了と報告する前(途中経過を判断に渡すときも) | スキル `self-review`(`working-norms.md`「報告の基準」を当てる) |

## 役割の呼び方

規範が「上位モデル」「下位モデル」と呼ぶのは、能力の一般的な序列ではなく、この運用での役割。

- **orchestrator** — タスク選定・委譲・検証の実行・着地処理。メインセッション
- **implementer**(standard)/ **implementer-advanced**(advanced)— 実装。どちらを使うかは台帳の実装 tier で決まる
- **reviewer** — 実装の文脈を持たずに行う独立レビュー

どのモデルがどの役割に当たるか、role の起動方法、ツール固有の事情は、使っているツールの runtime adapter(`runtime/claude.md` / `runtime/codex.md` / `runtime/kiro.md`)が正。
**3役すべてに同じモデルを割り当ててよい。** その場合、規範のうち「上位モデルなら省いてよい」と書かれた項目は**省かない**(省く判断の主体が居なくなるため)。
