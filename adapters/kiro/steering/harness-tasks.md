# spec の tasks.md の書き方(ハーネス用)

このワークスペースでは、spec の `tasks.md` をスキル `next-task` が台帳として読む。
読み替えの正は `~/.agent-norms/runtime/kiro.md`「台帳」。ここに書くのは、タスクを洗い出して `tasks.md` を書くときに守ること。

## 粒度

- **トップレベルの番号付きタスク1つ = レビューと MR/PR 1件の単位。** 1件の差分をレビュー担当が1回で読み切れる大きさにする
- サブタスクはそのタスクの実装手順。サブタスクだけを別の MR/PR にしたいなら、トップレベルのタスクに上げる
- 論理変更の単位で細かく割りすぎない。台帳が膨らむと、依存と順序の管理が実装より高くつく

## 各トップレベルタスクに付ける箇条書き

Kiro が生成した本文・サブタスク・要件参照(`_Requirements: …_`)はそのまま残し、その下に次の行を足す。

```markdown
- [ ] 2. <タスク名>
  - <Kiro が生成した本文・サブタスク>
  - _Requirements: 1.1, 2.3_
  - 状態: 未着手
  - 種別: 機能
  - impl: standard
  - deps: <spec名>/1
  - DoD: <検証できる条件を1行に1つ>
  - DoD: 静的検査とテストが green
```

- **状態**: `未着手` / `実装中` / `レビュー中` / `完了` のどれか。意味と遷移は `~/.agent-norms/templates/TASKS.md.template` の「状態と記録」と同じ
- **種別**: `機能` / `基盤` / `修正` / `修正(重大)`。定義と選ぶ順は 同じテンプレートの凡例と同じ
- **impl**: `standard`(既定)か `advanced`。仕様の暗黙の制約・横断的な不変条件・永続化形式・網羅性が問われる検査を含むタスクは `advanced`
- **deps**: 先に完了していなければならないタスクの ID(`<spec名>/<番号>`)。無ければ `なし`。Kiro が推定する依存とは別に、**必ず明示する**
- **DoD**: 完了の定義。検証できる形で書く。そのタスク固有の検証(名指しのテスト・確認手順)はここに書く — orchestrator はここに名指しされたものを自分で実行する

## やらないこと

- タスクのチェックボックスを状態の代わりにしない。状態は `状態:` の行が正
- 実行記録(ブランチ・MR/PR・検証の所在)を `tasks.md` に書かない。`.kiro/specs/<spec名>/runs.md` に書く
- 完了したタスクを消さない。不要になったタスクは取り消し線と理由を残す
